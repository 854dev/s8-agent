# 실제 모델 카운터 개발 테스트

## 실행

```bash
node pi/bin/counter-smoke.mjs --check
node pi/bin/counter-smoke.mjs
```

- Node.js와 로컬 Pi 의존성, 실행 가능한 Docker가 필요하다.
- 기본 인증은 Pi SDK가 기존 `~/.pi/agent/auth.json`을 내부적으로 사용한다. 다른 Pi 인증 경로는 `--auth-path PATH`로 지정한다. 인증 원문이나 실제 `.env`를 읽어 출력하지 않는다.
- `--provider NAME`, `--model ID`로 사용할 모델을 지정한다. 실행 전 확인된 모델만 사용하고 인증 없는 대체 실행은 하지 않는다.
- 기본 요청은 “리액트 Vite로 카운터 만들기”다. 현재는 이 시나리오 전용이며 임의 개발 작업 실행기로 사용하지 않는다.
- 실제 모델 호출과 의존성 다운로드가 발생한다. 전체 실행 한도는 10분, 역할별 최대 24턴·50회 도구 호출, 개발 검증은 최대 3회다.

## 실제 실행 흐름

```text
사용자 요청
  → 실제 매니저 모델: projectman 도구로 작업 생성
  → 감독 코드: 로컬 테스트 작업 선점
  → 실제 개발 모델: 허용된 프로젝트 파일 작성
  → Docker: 의존성 설치 → 독립 버튼 테스트 → Vite 빌드
  → 감독 코드: 최종 파일 재검증
  → 실제 매니저 모델: 결과 조회·검토 기록
```

- 매니저는 `projectman`만 사용한다. 개발 파일·셸 도구는 주지 않는다.
- 이번 `projectman`은 `local-smoke` 테스트 저장소다. 운영 PH-CMS Projectman API·승인·분산 선점·HITL UI 통합을 검증하지 않는다.
- 개발 모델은 실제 별도 Pi SDK 세션으로 실행되며, 영속 Pi 대화 세션 대신 실행 기록으로 결과를 보존한다. 운영 개발 CLI 프로세스 분리·병렬 실행 검증과는 구분한다.
- 개발자는 `workspace`, `run_checks`, `request_decision`만 사용한다. 쓰기는 새 테스트 폴더의 고정 파일 목록으로 제한한다.
- 쓰기 허용: `package.json`, `index.html`, `src/App.jsx`, `src/main.jsx`, `src/styles.css`, `README.md`. 링크·다른 경로·임의 의존성·설치 훅·임의 npm 명령을 허용하지 않는다.
- 설치는 고정된 의존성과 `--ignore-scripts`로 수행한다. 테스트·빌드는 네트워크 없는 제한된 컨테이너에서 수행하며 호스트 인증정보를 전달하지 않는다.
- 검증 코드는 감독 코드가 제공하고 컨테이너에 읽기 전용 마운트한다. 성공 주장을 믿지 않고 최종 소스 해시와 실제 결과를 확인한다.
- 질문이 반환되면 작업은 `blocked`가 되고 이후 개발 도구는 실행하지 않는다. 인간 답변·자동 재개는 이 시나리오에서 구현하지 않는다.

## 성공 조건

- 실제 매니저가 작업을 생성하고, 실제 개발자가 코드를 작성한다.
- 카운터 초깃값 0, 증가·감소와 초기화 동작의 독립 테스트 3개를 통과한다.
- 현재 숫자는 `aria-label="카운터"`, 버튼 이름은 `증가`, `감소`, `초기화`로 확인한다.
- Vite 빌드가 성공하고 `dist/index.html`과 JavaScript 산출물이 있다.
- 감독 코드의 최종 재검증과 매니저의 검토 기록이 모두 있어야 `ok=true`다.
- 테스트는 jsdom의 실제 React DOM 상호작용이다. 브라우저 시각 검증·배포·운영 Projectman 연동까지 통과했다고 보고하지 않는다.

## 산출물

```text
.s8-runtime/smoke/<run-id>/
├── request.json                 # 사용자 요청·실행 식별자
├── projectman.local.json         # 로컬 작업 상태·검토·전이 기록
├── manager-plan.events.jsonl     # 매니저 입력·공개 응답·도구 이벤트
├── developer.events.jsonl        # 개발 입력·공개 응답·도구 이벤트
├── manager-review.events.jsonl   # 매니저 결과 검토
├── checks-<n>.json               # 개발 중 독립 검증 결과
├── result.json                  # 최종 감독 검증·매니저 보고
├── checks/                      # 감독자 수용 테스트
└── workspace/                   # 개발자가 만든 카운터 프로젝트
```

- 모델 내부 추론과 인증 원문은 보관하지 않는다. 공개 기록의 문자열에는 기존 민감정보 마스킹을 적용한다.
- 인증·모델 오류는 원문 대신 실패 상태를 기록한다. 실패한 실행은 완료로 표시하거나 자동 재실행하지 않는다.
- 실행 결과는 로컬 런타임이며 Git에 포함하지 않는다. 위 CLI를 다시 실행하면 새 실행 ID와 폴더를 생성한다.
