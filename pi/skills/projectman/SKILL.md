# Projectman 공통 사용법

Projectman은 작업·계획·실행·결과의 기록이다. 작업 방식과 파일·명령·Git 사용은 시스템 프롬프트와 매니저 지시로 판단한다.

## 역할과 도구

- 매니저의 `projectman get`은 항목 조회다. 등록·위임·검토는 [projectman-manager](../projectman-manager/SKILL.md)를 참고한다.
- 워커의 `projectman get`은 조회와 claim을 함께 한다. 읽기 전용 조회로 생각하지 않는다. 수행·보고는 [projectman-worker](../projectman-worker/SKILL.md)를 참고한다.
- 범용 에이전트에는 기본적으로 Projectman 도구와 연결 설정이 없다. 이 스킬을 읽었다고 도구·인증·실행 권한이 생기지 않는다. 사용자가 Projectman 조작을 원하면 매니저 실행 경로를 안내한다. 실제 `.env`나 인증 파일을 열어 연결을 시도하지 않는다.
- 자신의 역할별 스킬은 해당 프로필에 제공된다. 다른 역할의 설명을 참고해도 그 역할의 도구를 사용할 수 있다고 가정하지 않는다.

## 항목과 상태

`workspace → project → task → subtask` 구조다. work는 별도 저장 타입이 아니라 task를 가리킨다. workspace는 기존 UID를 선택한다. project는 workspace 안의 코드베이스에 대응하며 `repoPath`는 시작 디렉터리다.

| 상태 | 의미 |
| --- | --- |
| `todo` | 등록·계획 정리 및 실행 전 검토 |
| `ready` | 사람이 계획을 확정해 실행 대기 |
| `doing` | 실행이 claim되어 진행 중 |
| `review` | 성공 보고를 받고 결과 검토 중 |
| `blocked` | 실패·중단 결과가 기록됨 |
| `done` | 사용자가 결과를 확인하고 최종 완료 |

상태 이름만으로 판단하기 어려우면 현재 `workflow`의 revision·spec·run·result·review를 함께 확인한다. claim이나 report의 성공은 모델의 설명이 아니라 서버 응답으로 확인한다.

## 실행 환경과 협업

- 실행기는 작업 디렉터리에서 직접 시작한다. 장비별 `communication.repositories` 매핑은 선택 사항이다. Git 초기화·저장소 루트·worktree·remote를 착수 조건으로 요구하지 않는다.
- 선행 결과의 패치 적용·Git 게시·원격 코드 전달은 자동으로 수행되지 않는다. 필요한 전달·반영 방법은 매니저와 워커가 결정한다. 기존 worktree의 변경도 자동 이동되지 않는다.
- 파일·명령 도구는 claim 전·보고 후·조사 세션에서도 차단되지 않는다. Projectman 서버의 상태·revision·인증 규칙은 별도로 적용된다.
- `agent_message`는 매니저가 모든 협업을 중개한다. `pending`은 전달 대기, `injected`는 Pi 주입 관찰이며 읽음·작업 완료가 아니다. 오프라인 전달은 보장하지 않는다. 연결 실패는 작업 취소나 재배정 승인이 아니다.

## 오류와 응답 유실

- `409`이면 최신 workflow를 조회해 revision·현재 run·기존 반영 여부를 확인한다. 새 요청 ID로 같은 변경을 무작정 반복하지 않는다. 같은 요청 ID에는 같은 내용을 사용한다.
- claim·report는 실행기가 요청 ID를 저장해 재전송한다. 타임아웃이 나도 서버에는 반영되었을 수 있다. 성공을 추측하거나 이미 기록한 보고를 다른 내용으로 덮어쓰지 않는다.
- 조회·통신 실패의 사실과 필요한 판단을 매니저에게 알리고 독립적으로 가능한 작업은 계속한다. 다른 워커의 실행이 사라졌다고 추측해 작업을 가로채지 않는다.
- 서버는 `completed` 보고에 실패한 검증·미완료 항목·실행 오류를 허용하지 않는다. 실제 완료에 필요한 일이 남으면 `failed`, 완료를 막지 않는 참고사항은 `decisions`로 기록한다. 오류를 숨겨 서버 검증을 통과시키지 않는다.
- 인증 오류는 운영자에게 연결 설정 확인을 요청한다. 실제 `.env`·비밀정보를 조회하거나 보고에 복사하지 않는다.
